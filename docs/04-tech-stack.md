# 04 · Tech Stack Summary
**ExoSpot – สรุปเทคโนโลยี โมเดล AI อุปกรณ์ฮาร์ดแวร์ และข้อมูลที่แอปแสดง**

---

## 1. Tech Stack แยกตามส่วน

### 1.1 AI / Computer Vision
- **ภาษา:** TypeScript (รันในเบราว์เซอร์)
- **Library:** `@mediapipe/tasks-vision` (Google MediaPipe Tasks)
- **API ที่ใช้:** `PoseLandmarker` + `DrawingUtils`
- **รับภาพกล้อง:** `getUserMedia` (WebRTC Media Capture)
- **วาดโครงกระดูก:** HTML Canvas 2D
- **การคำนวณ:** เขียนเอง (vector math, One Euro Filter, state machine)
- **การประมวลผล:** WebGL (GPU) ผ่าน WebAssembly · fallback เป็น CPU

### 1.2 Hardware
- **Microcontroller:** ESP32 DevKit V1
- **ภาษา:** C++ (Arduino framework)
- **IDE:** Arduino IDE 2 + บอร์ด `esp32 by Espressif`
- **การสื่อสาร:** USB Serial 115200 baud ↔ Web Serial API ในเบราว์เซอร์
- **Protocol 2 ทาง:** แอป → ESP32 `G` `Y` `R` `O` `C` `P` / ESP32 → แอป `READY` `LED:x` `TIMEOUT` + heartbeat 1 วินาที + failsafe 3 วินาที

### 1.3 Application
- **Frontend:** React + Vite + TypeScript
- **UI:** Tailwind CSS (สไตล์ glassmorphism ตาม reference)
- **Font:** IBM Plex Sans Thai / Noto Sans Thai
- **กราฟ:** Recharts
- **โค้ชเสียง (NLP):** Web Speech API – Text-to-Speech และ Speech-to-Text ภาษาไทย (`th-TH`), NLG แบบคลังประโยคหลายบุคลิก, LLM ผ่าน Supabase Edge Function
- **Backend / Database:** Supabase (PostgreSQL, Auth, Realtime, Edge Functions)
- **แจ้งเตือนลูกหลาน:** LINE Messaging API ผ่าน LINE Official Account
- **Deploy:** Vercel (HTTPS)
- **ออกแบบ UI:** Figma
- **จัดการโค้ด:** GitHub

### 1.4 เบราว์เซอร์ / อุปกรณ์ที่รองรับตอน Demo
- Google Chrome หรือ Microsoft Edge บน laptop (Windows / macOS)
- เหตุผล: Web Serial API ยังไม่รองรับบนมือถือและ Safari

## 2. โมเดล AI ที่ใช้

### 2.1 โมเดลหลัก: MediaPipe Pose Landmarker
- **ผู้พัฒนา:** Google
- **สถาปัตยกรรม:** BlazePose (2 ขั้น คือ detector หาตัวคนก่อน แล้วใช้ landmark model หาจุดข้อต่อ)
- **Output:** จุดข้อต่อ 33 จุดทั่วร่างกาย แต่ละจุดมี
  - `x, y` บนภาพ (0–1) + `z` ความลึกโดยประมาณ
  - `visibility` ความมั่นใจว่าจุดนั้นมองเห็น
  - `worldLandmarks` พิกัด 3 มิติหน่วยเมตร (จุดกลางสะโพกเป็นจุดอ้างอิง)
- **จุดที่โปรเจกต์ใช้:** hip (23, 24) · knee (25, 26) · ankle (27, 28) · heel (29, 30) · foot index (31, 32)

**ขนาดโมเดลให้เลือก**
- `pose_landmarker_lite` → เร็วที่สุด **ใช้เป็นค่าเริ่มต้น** เหมาะกับ laptop ทั่วไป
- `pose_landmarker_full` → สมดุลระหว่างความเร็วและความแม่น
- `pose_landmarker_heavy` → แม่นที่สุดแต่ช้า ใช้กับเครื่องที่มี GPU แรง

**เหตุผลที่เลือก**
- รันในเบราว์เซอร์ได้แบบ real-time ไม่ต้องมี server
- ภาพไม่ออกจากเครื่องผู้ใช้ ตอบเรื่อง PDPA ได้
- ฟรี และเป็น open source (Apache 2.0)
- ให้พิกัด 3 มิติ ทำให้คำนวณมุมเข่าได้แม่นขึ้นแม้กล้องเอียง

### 2.2 ส่วนที่ไม่ใช่โมเดล (Rule-based)
การตัดสินว่าท่าเสี่ยงไหมใช้ **กฎที่นักกายภาพกำหนด** ไม่ได้ train โมเดลใหม่:
- มุมเข่า (knee angle)
- เข่าบิดเข้าใน (valgus ratio)
- ความเร็วลุก/นั่ง (angular velocity)
- การลงน้ำหนักไม่เท่ากัน (asymmetry)

เหตุผล: อธิบายผลได้ นักกายภาพปรับเกณฑ์ได้ และไม่ต้องใช้ข้อมูลผู้ป่วยจำนวนมากเพื่อ train

### 2.3 โมเดลภาษา (NLP) สำหรับโค้ชเสียง
- **LLM: Claude (`claude-haiku-5-5`)** ผ่าน Supabase Edge Function `coach-llm` แต่งคำทักทายก่อนฝึกและสรุปผลหลังฝึกแบบไม่ซ้ำเดิม ส่งเฉพาะตัวเลข ไม่ส่งชื่อหรือภาพ ถ้าไม่ตอบภายใน 4 วินาทีใช้ประโยคสำเร็จรูป
- **Text-to-Speech:** เสียงภาษาไทยของเบราว์เซอร์ (Web Speech API) ปรับความเร็ว/ระดับเสียงตามบุคลิก
- **Speech-to-Text:** Web Speech API ของ Chrome (th-TH) + จับคำสั่งด้วยกติกา keyword (pause / resume / finish / count / start)
- ระหว่างฝึกใช้ NLG แบบกฎ + คลังประโยคในเครื่อง เพราะต้องเตือนเร็วกว่า 0.3 วินาที

## 3. อุปกรณ์ฮาร์ดแวร์

### 3.1 ฝั่งผู้ใช้ (มีอยู่แล้วที่บ้าน)
- Laptop ที่มี webcam (หรือใช้มือถือเป็นกล้องผ่าน DroidCam / Iriun)
- เก้าอี้มีพนักพิง ไม่มีล้อ สำหรับท่าลุกจากเก้าอี้

### 3.2 กล่องไฟ LED แจ้งเตือน (ไม่มี buzzer)
- ESP32 DevKit V1 × 1
- LED สีเขียว × 1 (ท่าถูก)
- LED สีเหลือง × 1 (เริ่มเสี่ยง)
- LED สีแดง × 1 (อันตราย)
- ตัวต้านทาน 220 Ω × 3
- Breadboard 830 จุด × 1
- สาย jumper ผู้-ผู้ ประมาณ 12 เส้น
- สาย USB ที่ส่งข้อมูลได้ × 1
- กล่องพลาสติกหรือกล่องพิมพ์ 3D × 1

### 3.3 การต่อขา
- `GPIO25` → LED เขียว
- `GPIO26` → LED เหลือง
- `GPIO27` → LED แดง
- `VIN` (5V) และ `GND` → รางไฟของ breadboard

## 4. ข้อมูลที่ Application แสดง

### 4.1 หน้าหลัก (Home)
- คำทักทายพร้อมชื่อเล่นผู้สูงอายุ และวันที่
- จำนวนครั้งที่ทำวันนี้ เทียบกับเป้าหมาย (วงแหวน progress)
- เปอร์เซ็นต์ท่าถูกของวันนี้
- คะแนนปวดล่าสุด
- โปรแกรมฝึกวันนี้ + ปุ่มเริ่มฝึก
- สถานะการเชื่อมต่อกล่องแจ้งเตือน

### 4.2 ระหว่างฝึก (Live Session)
- ภาพกล้องพร้อมโครงกระดูก ขาเปลี่ยนสีตามสถานะ
- มุมเข่าซ้าย-ขวาแบบ real-time
- ตัวนับครั้ง เช่น 4 / 10
- แถบสถานะ: ดีมาก / ระวัง / หยุดปรับท่า / ถอยให้เห็นทั้งตัว
- โค้ชเสียงพูดนับครั้ง เตือนท่าผิด และชม ตามบุคลิกที่เลือก
- ไฟจำลองแสดงสถานะไฟจริงที่ ESP32 รายงานกลับ
- ข้อความ "ได้ยินว่า…" เมื่อใช้คำสั่งเสียง

### 4.3 สรุปผลหลังฝึก
- จำนวนครั้งที่ทำ และจำนวนครั้งที่ทำถูก (%)
- ประเภทท่าผิดและจำนวนครั้ง (เข่าบิด, นั่งเร็ว, ลงน้ำหนักไม่เท่ากัน)
- เวลาเฉลี่ยต่อครั้ง
- ช่วงมุมงอเข่า (ROM)
- คะแนนปวดก่อนและหลังฝึก

### 4.4 สถิติ (Statistic)
- กราฟแท่งรายวันของสัปดาห์ / เดือน
- แท็บ: จำนวนครั้ง · ท่าถูก % · ความปวด
- กราฟมุมเข่าของการฝึกครั้งล่าสุด
- ข้อความสรุปแนวโน้ม เช่น "เข่าบิดลดลง 40% จากสัปดาห์ก่อน"

### 4.5 โปรไฟล์
- ชื่อ รูป และกลุ่มผู้ป่วย (ยังไม่ผ่าตัด / ผ่าตัดแล้ว)
- อายุ · ส่วนสูง · น้ำหนัก
- จุดที่ต้องระวัง (เข่าข้างที่เป็นและข้อจำกัดจากแพทย์)
- ตั้งค่าการแจ้งเตือน และเสียง
- รายชื่อผู้ดูแลที่เชื่อมไว้

### 4.6 ลูกหลาน (Dashboard + LINE)
- วันนี้ผู้สูงอายุฝึกแล้วหรือยัง
- สรุปผลหลังฝึกแต่ละรอบ
- แจ้งเตือนเมื่อไม่ได้ฝึกติดกัน 2 วัน หรือคะแนนปวดสูง

### 4.7 นักกายภาพ
- รายชื่อผู้ป่วยและสถานะล่าสุด
- ประวัติการฝึกรายครั้งอย่างละเอียด
- หน้าตั้งเกณฑ์ความปลอดภัยรายบุคคล
